# ZCU102 Q8_0 矩阵乘 PL 原型验证

日期：2026-08-22  
器件：XCZU9EG-FFVB1156-2-E（ZCU102）  
工具：Vitis HLS 2023.2  
状态：C 仿真、HLS 综合、Verilog C/RTL 联合仿真通过；尚未生成 bitstream，尚未烧录。

## 1. 开发方式结论

第一阶段采用 **HLS 为主、RTL 为辅**：Q8_0 解包、动态矩阵尺寸、分块和 AXI
访存控制适合用 C++ 快速迭代；综合报告可直接暴露循环 II、延迟和资源瓶颈。完成
系统级验证后，只对 HLS 无法高效实现的关键数据通路（例如定点归约树、稀疏调度、
特殊缓存控制）改用手写 SystemVerilog。当前不宜一开始全手写 RTL。

## 2. 原型功能与数据格式

- 运算：`Y[M,N] = X[M,K] * W[N,K]^T`。
- 权重：GGML Q8_0，每 32 个 int8 权重共享一个 FP16 scale。
- 板端布局：将原始 34 Byte block 无损拆成 256-bit 权重面和 16-bit scale 面，
  避免 AXI 上的非对齐访问；这不是再次量化。
- 激活和累加：FP32。
- Tile：`TM=16`、`TN=64`、`K-block=32`，4 个并行输出 PE。
- 接口：权重、scale、激活、输出分别使用独立 AXI master，控制使用 AXI-Lite。
- 支持运行时 M/N/K，覆盖 GEMV 和 GEMM；当前结构针对较大 M 的 prefill/encoder，
  M=1 decoder 仅保证功能正确，尚未做专用优化。

## 3. 验证结果

### C 仿真

全部通过：

- `3x5x64` 小矩阵；
- `1x7x96` GEMV；
- `17x65x32` 跨 M/N tile 边界；
- RoboBrain `K=2560`；
- 视觉编码器 `K=1024`；
- FP16 零 scale、最小 subnormal、int8 的 -128/+127；
- K 非 32 对齐和维度越界。

相对独立参考实现的最大绝对误差为 `2.0980835e-05`。误差来自 HLS C 模型的
FP16/FP32 仿真语义，不改变 Q8_0 权重位模式。

### HLS 综合

目标周期 5.00 ns（200 MHz），综合估算关键路径 3.650 ns（273.97 MHz）。该数值
尚未经过 Vivado 布局布线，不能视为板上已达到的频率。

| 资源 | 使用 | ZU9EG 总量 | 占比 |
|---|---:|---:|---:|
| DSP | 655 | 2520 | 26.0% |
| BRAM18K | 80 | 1824 | 4.4% |
| LUT | 58,902 | 274,080 | 21.5% |
| FF | 81,202 | 548,160 | 14.8% |

连续计算循环达到 `II=1`、深度 67。单个 K-block 的最低调度延迟约 982 周期，
第一版约 2018 周期，核心调度约加速 `2.05x`。FP16 subnormal scale 的转换包含
归一化循环，综合最坏延迟会更高；应在权重预打包阶段统计真实 scale 分类。

### Verilog C/RTL 联合仿真

XSim 对 5 个硬件事务全部通过，覆盖小矩阵、M/N 边界和非法输入。报告结果：

- Verilog status：Pass；
- RTL latency：75 / 3907 / 8391 cycles（min/avg/max）；
- 总执行：19,483 cycles。

## 4. 典型矩阵的综合级时延估算

采用目标 200 MHz、正常 scale 对应的最低 HLS 调度，单 tile 近似：

`cycles_tile = 2065 + (K/32) * 982`

| 代表矩阵 MxNxK | Tile 数 | 估算周期 | 200 MHz 估算 |
|---|---:|---:|---:|
| 512x9728x2560 | 4,864 | 392,160,000 | 1.961 s |
| 4320x4096x1024 | 17,280 | 578,689,920 | 2.893 s |
| 1x9728x2560 | 152 | 12,255,000 | 61.3 ms |

这些是**单次矩阵乘内核的综合级估算**，不是整层、整模型或板上实测。它没有计入
AXI interconnect 竞争、DDR 有效带宽、驱动开销和布局布线降频，因此不能据此宣称
端到端加速。当前实现还会随 M tile 重读权重，真实系统必须通过数据复用、双缓冲和
算存重叠解决。

## 5. 当前判断与下一步

该原型证明了 Q8_0 解包与矩阵乘可以在 ZCU102 PL 上正确综合和运行 RTL 仿真，
但 FP32 dot tree 仅 4 个并行输出就消耗 655 DSP，资源效率不足以支撑 3--5 Hz 图片
推理目标。下一版应先完成两项设计空间比较：

1. prefill/encoder 路径：激活定点化，采用 INT8xINT8/INT8xINT16 MAC、宽整数累加，
   在输出端融合 scale，以相同 DSP 获得更多 PE；
2. decoder 路径：为 M=1 建独立 GEMV 数据流，缓存激活并流式扫权重，避免沿用
   `TM=16` 的空计算开销。

随后再加入 ping-pong buffer 和 AXI 性能模型，完成 Vivado block design、布局布线
和板上 DDR 实测。仍须遵守“先仿真，后烧录”。
